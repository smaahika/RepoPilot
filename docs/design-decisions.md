# Design Decision Log

Decisions are recorded when they constrain later work. Status is either **accepted**, **proposed**,
or **superseded**.

## ADR-001: Use an explicit controller-owned state machine

- **Status:** accepted
- **Context:** A language model can suggest useful actions but cannot reliably enforce budgets,
  transitions, or stopping conditions.
- **Decision:** Encode legal states and transitions in application code. Model responses are inputs
  to controller decisions, never transition commands.
- **Consequences:** Runs become testable and inspectable. Adding new phases requires deliberate
  transition and failure-path changes.

## ADR-002: Use direct provider adapters instead of an agent framework

- **Status:** accepted
- **Context:** The portfolio signal is orchestration and safety behavior. A large framework would
  hide those mechanisms and expand the dependency surface.
- **Decision:** Define a small internal model protocol and implement direct SDK adapters behind it.
- **Consequences:** RepoPilot owns retries, schema validation, and usage accounting. Provider support
  is initially narrow, but adapters can be replaced without changing the controller.

## ADR-003: Use Pydantic at untrusted boundaries

- **Status:** accepted
- **Context:** Task requests, configuration, model responses, and tool arguments require runtime
  validation in addition to static typing.
- **Decision:** Use Pydantic v2 models for boundary data and typed Python structures internally when
  validation is unnecessary.
- **Consequences:** Schemas and validation errors are consistent. Core logic must avoid coupling
  every internal value to Pydantic.

## ADR-004: Never execute shell text generated by a model

- **Status:** accepted
- **Context:** Shell parsing enables composition, expansion, redirection, and execution beyond the
  intended command.
- **Decision:** The command tool accepts tokenized argument vectors, validates the executable and
  arguments against policy, and invokes subprocesses without a shell.
- **Consequences:** Complex shell pipelines are unavailable. Supported verification commands must
  be represented explicitly or approved as project-specific argv patterns.

## ADR-005: Keep artifacts separate from the disposable workspace

- **Status:** accepted
- **Context:** The workspace is temporary and contains untrusted repository content, while reports
  and logs must survive cleanup.
- **Decision:** Store run artifacts in a sibling run directory with separate lifecycle management.
- **Consequences:** Cleanup cannot accidentally remove the report. Both locations require careful
  ownership, size limits, and secret redaction.

## ADR-006: Start with argparse for the CLI

- **Status:** accepted
- **Context:** Day 1 needs a stable entry point, while the final command structure is not yet known.
- **Decision:** Use the standard library's `argparse` initially. Reconsider Typer only if nested
  commands or richer parameter validation justify another runtime dependency.
- **Consequences:** The skeleton installs and runs with fewer dependencies. Some CLI ergonomics may
  require more explicit code later.
